## Logic survivors left after run 3, and why

Equivalent (the program behaves the same):

- `urllib.request.Request(..., method="POST")` → no method or `None`
  (model_drafting `_create`, pager `send_page`): a request with a body is a
  POST either way.
- pager `save_config` file mode 0o600 → none or 0o601: the file is
  `chmod`-ed to 0600 right after.
- `encoding="utf-8"` → default (pager load/save): `json.dump` writes ASCII,
  which every default encoding reads and writes the same.
- `"verbatim_available": True` → `False` on clarification provenance
  (drawer_filing `_hold`, handoff_guard): nothing reads this flag.
- drawer_filing `_identity`: `assigned_agent="00"` dropped (the default is
  "00"); manifest `.get(..., "")` → `None` and `m.get("role", "client")` →
  `None` on a fill (a manifest written by `provision_drawer` always has the
  name, address and role keys; a drawer folder with no manifest would differ).
- clock: `CHECKS.get(agent, [])` / `getattr(spoke, source, {})` /
  `state.get(ctx, {})` defaults (the clock only ticks agents listed in `CHECKS`; every
  agent has its state attribute; contexts come from that same state).
- readable_audit: `e.get("ts", 0)` → `1` (every chain entry has a time).
- 08 `check_disclosure_deadlines` `continue` → `break` after a bad date: only
  one disclosure document type exists, so nothing follows it.

Not covered by these tests:

- `readable_logger.generate_eod_report`: 32 logic survivors, unchanged since
  run 1. This is the readable logger's report writer, not code written on
  2026-10-12; it is in scope because the console's EOD ledger now calls it.
